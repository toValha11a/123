## 7. Анализ покрытия и план доработки

По итогам сверки тест-кейсов с исходным кодом выявлены сценарии, которые пока **не покрыты** тест-кейсами. Они включены в план следующей итерации тестирования.

### 7.1. Непокрытые сообщения валидации

| Окно | Сообщение в коде | Условие появления |
|---|---|---|
| Главное меню | «В папке не найден файл export_descr_unit.txt!» | Папка существует, но в ней нет файла характеристик |
| Редактирование юнита | «<Поле> не может быть пустым!» | Поле характеристики очищено перед сохранением |
| Редактирование юнита | «<Поле> должно быть в диапазоне от 1 до 100!» | Значение вне диапазона (для дальности — 1…400) |
| Расчёт пропорций | «Заполните только одно из игровых полей!» | Заполнены оба игровых поля |
| Расчёт пропорций | «Игровая общая численность должна быть положительным числом!» | В поле введено 0 или отрицательное число |
| Расчёт пропорций | «Игровая численность отряда должна быть положительным числом!» | В поле введено 0 или отрицательное число |

### 7.2. Тест-дизайн: граничные значения

Допустимые диапазоны полей взяты из исходного кода (`createNumberField(min, max)`). Поле подсвечивается красной рамкой при выходе за диапазон.

| Поле | Диапазон | Граничные значения для проверки |
|---|:---:|---|
| Атака, натиск, доспех, щит, умение защиты | 1 – 100 | `0` 🔴 · `1` 🟢 · `2` 🟢 · `99` 🟢 · `100` 🟢 · `101` 🔴 |
| Дальность полёта снаряда | 1 – 400 | `0` 🔴 · `1` 🟢 · `400` 🟢 · `401` 🔴 |
| Реальная численность (общая / отряда) | 1 – 500 000 | `0` 🔴 · `1` 🟢 · `500000` 🟢 · `500001` 🔴 |
| Игровая численность (общая / отряда) | 1 – 40 000 | `0` 🔴 · `1` 🟢 · `40000` 🟢 · `40001` 🔴 |

Дополнительно для числовых полей: отрицательное число, дробное число (`10.5`), пробелы по краям, очень длинная строка, спецсимволы.

### 7.3. Гипотезы о дефектах (требуют воспроизведения)

| № | Гипотеза | Основание | Шаги для проверки |
|:---:|---|---|---|
| Г-1 | Нельзя сохранить юнит без второго оружия, щита или оружия дальнего боя | Для таких юнитов в полях выводится `0` (см. руководство пользователя), а валидация при сохранении требует значения от 1 | ПУ-2 → «Изменение характеристик» → найти юнит без щита → изменить любое поле → «Сохранить» |
| Г-2 | Поиск юнита находит первое частичное совпадение | Поиск выполняется проверкой вхождения подстроки в название | Ввести часть названия, общую для нескольких юнитов (например, «конница»), → «Найти» |
| Г-3 | Ошибка согласования в тексте сообщений | Шаблон «<Поле> должно быть…» даёт «Атака … должно быть числом!» | Ввести буквы в поле «Атака первым оружием» → «Сохранить» |
| Г-4 | Unit-тесты не запускаются командой `mvn test` | Тесты лежат в `test/java`, а не в стандартном `src/test/java`, и `testSourceDirectory` в `pom.xml` не задан | Выполнить `mvn test` в корне проекта и проверить число запущенных тестов |
